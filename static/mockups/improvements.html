Audit accessibilité (a11y) en CI

moyen

Contraste, alternatives d'images, ordre des titres, navigation clavier — vérifiés automatiquement (axe / Lighthouse CI).

Pourquoi : exigence forte pour une institution publique de l'UE ; empêche les régressions à la PR.

chantier

Pourquoi : Docusaurus gère i18n nativement ; locales est déjà là (EN seul). Gros gain d'audience UE.

Page publique Roadmap / Statut

faible

Une page « Roadmap » listant livré / en cours / prévu — générée depuis un simple fichier de données ou les issues GitHub.

Pourquoi : transparence sur l'évolution de la plateforme ; réutilise le style des cartes home existantes.

Note. Cette page est une maquette statique de proposition — rien n'est encore branché dans le site. Chaque carte représente une amélioration candidate ; l'aperçu illustre le rendu cible. L'objectif est de choisir ensemble lesquelles implémenter, dans quel ordre.

Suggestion de séquencement. Commencer par les quick wins à fort impact : ① widget « Page utile ? », ② barre de progression + TOC active, ③ bandeau d'annonce automatique, ④ pages liées. Puis les chantiers structurants : palette ⌘K, glossaire, « Copier pour LLM », audit a11y — et enfin i18n et versionnement, qui touchent l'arborescence.
